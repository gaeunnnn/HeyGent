## 작업 목적

- 자율 프로젝트 최종 산출물 제출 기준에 맞춰 루트 `exec` 폴더와 1~4번 제출 문서를 정리합니다.

## 변경 요약

- `exec/README.md`에 제출 산출물 라우팅 링크를 추가했습니다.
- `exec/1`에 포팅 매뉴얼을 작성했습니다.
- `exec/2`에 외부 서비스 연동 정보를 정리했습니다.
- `exec/3`에 고정 기준 데이터 없이 런타임 생성 데이터를 사용하는 DB 제출 기준과 `empty-db-dump.sql`을 추가했습니다.
- `exec/4`에 발표용 시연 진행 순서를 작성했습니다.
- 로컬 실행에 필요한 URL, 포트, Firebase project id, Android package name을 비밀값 없이 문서에 보강했습니다.
- 검토자 시점처럼 보이는 표현을 포팅 매뉴얼에 맞는 절차형 문장으로 정리했습니다.

## 테스트 / 확인

- `rg --files exec`로 제출 폴더 구조를 확인했습니다.
- README 링크 대상 파일 존재 여부를 확인했습니다.
- `rg -n "[ \t]+$"`로 추가 문서의 trailing whitespace가 없음을 확인했습니다.
- `rg`로 OpenAI/Firebase/인증 헤더 등 대표 secret 패턴이 `exec` 문서에 포함되지 않았음을 확인했습니다.
- `git diff --check`로 whitespace 오류가 없음을 확인했습니다.
- `.env` 계열 파일은 원문을 문서에 복사하지 않고, 키 이름과 비민감 설정값만 반영했습니다.
- 실행 테스트는 문서 추가 작업이라 별도 수행하지 않습니다.

## 결정 / 이슈

- DB는 사용 중 생성되고 소비되는 대화, 실행 기록, 연결 상태가 중심이라 별도 seed로 모아 복원할 고정 기준 데이터가 없습니다.
- 실제 외부 서비스 키와 토큰은 문서에 포함하지 않고 환경변수명과 설정 위치만 기록했습니다.
- 사용자가 `.env` 직접 확인을 허용했지만, 저장소 보안 규칙에 따라 secret 원문은 `exec` 문서에 남기지 않았습니다.
