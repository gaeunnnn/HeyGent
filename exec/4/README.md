# 4. 시연 시나리오

시연에 필요한 진행 순서를 정리한 문서입니다. 발표자는 역할명으로 구분합니다.

## 등장 역할

| 역할 | 설명 |
| --- | --- |
| 발표자 | 전체 진행, 기능 설명, 화면 전환 안내 |
| 남자 1 | 웹 서비스 로그인 및 에이전트 생성 사용자 |
| 여자 1 | 모바일/워치/헬스 데이터 확인 사용자 |
| 남자 2 | Mattermost와 Notion 결과 확인 보조 |

## 시연 전 준비

- Web: `http://localhost:5173` 접속 가능 상태
- Backend, AI, PostgreSQL, Redis, Mosquitto 실행
- 발표자 계정 로그인 가능
- Gmail, Notion, Mattermost 외부 서비스 연결 완료
- PC 브릿지 프로그램 실행 파일 또는 `python -m bridge.tray` 실행 준비
- 브릿지 작업 폴더 준비
- 모바일 앱 로그인 및 FCM 수신 가능 상태
- 필요 시 Samsung Health 권한 승인 완료
- SRT 예약 시연은 실제 결제/예약 리스크가 있으면 사전 녹화 또는 더미 결과 화면으로 대체

## 전체 흐름

1. 인트로 영상 재생
2. SRT 예약 요청을 먼저 던지고 결과는 뒤에서 확인
3. HeyGent 웹 로그인 및 대시보드 확인
4. 에이전트 작업공간과 기본 에이전트 생성 확인
5. 로컬 브릿지 페어링
6. 뉴스레터 정리 에이전트 생성
7. Gmail -> HTML 신문 생성 -> Notion 정리 -> Mattermost 공유 워크플로우 실행
8. 시각화 화면에서 에이전트 작업 추적
9. Notion, Mattermost, PC 폴더 결과 확인
10. 장기기억 또는 헬스 에이전트 선택 시연

## 시나리오 1. 인트로 뒤 백그라운드 요청

화면: 발표 장표 또는 HeyGent 채팅

발표자:

```text
본격적인 기능 설명 전에, HeyGent에게 목표만 하나 던져보겠습니다.
```

채팅 입력:

```text
이번 주 금요일 부산 출발 수서역 도착 SRT 오후 4시에서 6시 사이 열차 예약 걸어놓고, Mattermost 잡담 채널에 일정 공유해줘.
```

발표자:

```text
지금은 목표만 던졌습니다. 에이전트가 필요한 도구를 선택하고 작업을 진행하는 동안, 결과는 뒤에서 다시 확인하겠습니다.
```

확인 포인트:

- 작업이 실행 상태로 생성됨
- 에이전트 시각화 또는 작업 보드에 진행 상태가 표시됨
- 실제 예약 위험이 있으면 사전 녹화 또는 예약 완료 더미 화면으로 전환

## 시나리오 2. 로그인과 대시보드

화면: Web 로그인 -> 대시보드

남자 1:

```text
HeyGent 서비스를 처음 사용하는 사용자가 로그인합니다.
```

진행:

1. Kakao 또는 dev-login으로 로그인
2. 대시보드 진입
3. 연결된 서비스, 최근 작업, 건강 요약 영역 확인

발표자:

```text
대시보드에서는 에이전트 작업 상태와 연결된 서비스 정보를 한 번에 확인합니다. 모바일과 워치가 연결되어 있으면 건강 데이터도 에이전트가 참고합니다.
```

## 시나리오 3. 에이전트 작업공간 확인

화면: 에이전트 시각화 또는 건물/세션 화면

진행:

1. 에이전트 작업공간 화면으로 이동
2. 세션 또는 층 목록 확인
3. 비어 있는 작업공간 선택
4. 기본 에이전트 생성

발표자:

```text
처음 사용하는 사용자를 위해 기본 에이전트 구성을 제공합니다. 팀장 에이전트를 중심으로 역할별 에이전트가 생성되고, 이들이 작업을 나누어 처리합니다.
```

확인 포인트:

- 팀장 에이전트 표시
- Gmail, 디자이너, 헬스 등 역할별 에이전트 표시
- 작업공간 안에서 에이전트 상태가 시각적으로 보임

## 시나리오 4. 로컬 브릿지 페어링

화면: Web 브릿지 설정 + PC 브릿지 프로그램

발표자:

```text
클라우드에 있는 에이전트가 제 PC 안의 허용된 폴더에서 작업할 수 있도록 브릿지를 연결하겠습니다.
```

진행:

1. 웹에서 브릿지 설정 화면 진입
2. 새 페어링 코드 발급
3. PC에서 브릿지 프로그램 실행
4. 페어링 코드와 디바이스 이름 입력
5. 작업 폴더 선택
6. 웹에서 연결 상태 확인

확인 포인트:

- 브릿지 상태가 온라인으로 표시됨
- 작업 가능 폴더 경계가 명확히 표시됨
- 브릿지가 꺼져 있으면 로컬 PC 작업은 실행되지 않는다고 설명

## 시나리오 5. 뉴스레터 정리 에이전트 만들기

화면: 에이전트 생성 화면

발표자:

```text
이번에는 뉴스레터를 정리해주는 에이전트를 하나 만들어보겠습니다.
```

진행:

1. 에이전트 만들기 클릭
2. 이름 입력: `뉴스레터 정리 에이전트`
3. 역할 설명 입력

```text
사용자의 Gmail에서 뉴스레터를 찾아 핵심 내용을 한국어로 요약하고, 필요한 경우 Mattermost에 공유하는 에이전트입니다.
```

4. Gmail 스킬 선택
5. Mattermost 공유가 필요하면 Mattermost 스킬 선택
6. 저장

발표자:

```text
HeyGent에서는 에이전트의 캐릭터와 역할을 정하고, 필요한 스킬을 붙이는 방식으로 새 에이전트를 만들 수 있습니다.
```

확인 포인트:

- 새 에이전트가 목록에 추가됨
- Gmail 스킬이 연결됨
- 팀장 에이전트가 새 에이전트를 작업 후보로 인식할 수 있음

## 시나리오 6. 워크플로우 구성

화면: 워크플로우 또는 루틴 편집 화면

발표자:

```text
방금 만든 뉴스레터 정리 에이전트를 기존 업무 흐름에 끼워 넣어보겠습니다.
```

진행:

1. 새 워크플로우 생성
2. 시작 노드에 사용자 목표 입력

```text
오늘 받은 뉴스레터를 정리해줘.
```

3. `뉴스레터 정리 에이전트` 노드 추가
4. Gmail에서 뉴스레터 수집 및 요약 작업 연결
5. `디자이너 에이전트` 노드 추가
6. PC 브릿지 폴더에 HTML 신문 생성 작업 연결
7. `Notion 에이전트` 노드 추가
8. 오늘 날짜 뉴스 페이지 생성 작업 연결
9. Mattermost 공유 노드 추가
10. 실행 버튼 클릭

채팅 또는 실행 입력:

```text
오늘 Gmail 뉴스레터를 요약해서 Notion에 정리하고, PC 폴더에는 HTML 신문으로 저장한 뒤 Mattermost 잡담 채널에 링크와 요약을 공유해줘.
```

발표자:

```text
이렇게 HeyGent는 하나의 명령만 처리하는 것이 아니라 여러 에이전트가 각자 역할을 맡아 하나의 업무 흐름을 완성하도록 도와줍니다.
```

확인 포인트:

- 워크플로우 노드 간 연결 표시
- 실행 상태 전환
- 에이전트별 담당 작업 표시

## 시나리오 7. 작업 시각화 확인

화면: 에이전트 작업공간

진행:

1. 워크플로우 실행 후 시각화 화면으로 이동
2. 에이전트들이 작업하는 모습 확인
3. 말풍선 또는 상태 패널 확인
4. 작업 히스토리 확인

발표자:

```text
결과만 기다리는 것이 아니라 어떤 에이전트가 어떤 일을 하고 있는지 확인합니다. 진행 중인 작업은 말풍선과 히스토리로 추적됩니다.
```

확인 포인트:

- 뉴스레터 에이전트: Gmail 조회 및 요약
- 디자이너 에이전트: HTML 파일 생성
- Notion 에이전트: 페이지 생성
- Mattermost 공유 완료

## 시나리오 8. 결과 확인

화면: Notion, Mattermost, PC 폴더, 모바일 알림

진행:

1. Notion 페이지 열기
2. Mattermost 채널 메시지 확인
3. 브릿지 작업 폴더에서 HTML 파일 확인
4. 모바일 푸시 또는 앱 내 작업 완료 상태 확인

남자 2:

```text
Mattermost 채널에 요약과 링크가 공유되었습니다.
```

여자 1:

```text
모바일에서도 작업 완료 알림이 도착했습니다.
```

발표자:

```text
웹에서 시작한 일이 외부 서비스, 로컬 PC, 모바일 알림까지 이어집니다.
```

## 선택 시연 A. 장기기억

화면: 채팅 또는 메모리 관련 결과 화면

채팅 입력:

```text
나 어제 인프라 문제 때문에 힘들어했던 것 같은데, 그때 내가 뭐라고 했었지?
```

발표자:

```text
단어가 정확히 겹치지 않아도, HeyGent는 대화에서 저장된 기억을 의미 기반으로 찾아 응답에 반영합니다.
```

주의:

- 실제 개인 대화가 노출되지 않도록 시연용 기억만 미리 생성합니다.
- 민감하거나 부적절한 표현은 발표 전 더미 데이터로 정리합니다.

## 선택 시연 B. 헬스 에이전트

화면: 모바일 앱 또는 웹 채팅

채팅 입력:

```text
나 오늘 컨디션 좋은데 발표 마무리 잘할 수 있겠지?
```

발표자:

```text
헬스 에이전트는 최근 수면 시간이나 심박 데이터처럼 연결된 건강 정보를 참고해 답변할 수 있습니다.
```

확인 포인트:

- Samsung Health 권한 승인 상태
- 최근 수면, 심박 등 데이터 표시
- 건강 데이터가 없으면 더미 데이터 또는 설명 화면으로 대체

## 마무리 확인 멘트

발표자:

```text
시연에서 보신 것처럼 HeyGent는 목표만 입력해도 에이전트가 역할을 나누고, 외부 서비스와 로컬 PC까지 연결해 실제 결과물을 만들어냅니다.
```
