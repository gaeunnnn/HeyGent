# 헬스 컨디션 체크 스킬

## 사용 시점

사용자가 본인의 건강정보, 컨디션, 피로, 회복, 수면, 활동량, 운동 강도, 심박, 혈압, 칼로리, 체성분을 바탕으로 생활 코칭을 요청할 때 사용한다.
특정 일정이 명시되지 않아도, 사용자의 현재 몸 상태와 하루 활동 방향을 건강 데이터로 참고해 달라는 요청이면 이 스킬을 사용한다.

예시:

- "나 오늘 컨디션 좋은데 발표 마무리 잘 할 수 있겠지?"
- "어제 수면 시간, 수면 점수, 심박 변화, 걸음 수, 운동 기록을 바탕으로 오늘 컨디션을 3줄로 요약해줘."
- "오늘 무리해서 운동해도 될까?"
- "수면이랑 걸음 수 보고 오늘 피해야 할 행동 알려줘."
- "요즘 활동량이랑 수면 보면 몸 상태 괜찮아?"
- "내 건강 데이터 기준으로 오늘은 어떤 식으로 움직이는 게 좋을까?"

## 조회 데이터

현재 스킬은 아래 지표를 건강정보 참고 코칭 재료로 사용한다.

- `step_count` (`Int`): 걸음 수. 하루 활동량과 움직임 부족/과다 여부를 참고한다.
- `active_minutes` (`Int`): 활성 시간. 실제 활동 지속 시간을 참고한다.
- `total_calories` (`Decimal`): 총 칼로리. 하루 전체 에너지 소모 흐름을 참고한다.
- `active_calories` (`Decimal`): 활동으로 소비한 칼로리. 운동·활동 부담을 참고한다.
- `height_cm` (`Decimal`): 키(cm). 체성분 해석의 보조 맥락으로만 사용한다.
- `weight_kg` (`Decimal`): 몸무게(kg). 단일 수치로 건강을 단정하지 않고 추세 맥락으로만 사용한다.
- `body_fat_pct` (`Decimal`): 체지방률(%). 장기 체성분 관리 힌트로 참고한다.
- `muscle_mass_kg` (`Decimal`): 골격근량(kg). 근육량·운동 방향의 장기 힌트로 참고한다.
- `heart_rate_bpm` (`Int`): 심박수(BPM). 피로, 스트레스, 회복 상태의 주의 신호로 참고한다.
- `systolic_bp` (`Decimal`): 수축기 혈압. 활력 징후 주의 신호로 참고하되 진단하지 않는다.
- `diastolic_bp` (`Decimal`): 이완기 혈압. 활력 징후 주의 신호로 참고하되 진단하지 않는다.
- `duration_minutes` (`Int`): 총 수면 시간(분). 회복 상태의 우선 지표로 참고한다.
- `sleep_score` (`Int`): 수면 점수. 기기별 품질 지표이므로 추세와 참고 신호로만 사용한다.

## 런타임 도구

필요한 runtime toolset: `health`. 핵심 도구는 `health.execute` 하나다. backend Health 프록시를 통해 인증된 사용자의 `/api/v1/health/` 데이터를 조회한다.

모델 응답에 `userId` 를 절대로 넣지 않는다. 런타임이 인증된 사용자 식별자를 자동으로 바인딩한다.

상세 정보는 필요한 만큼만 읽는다.

- `references/health-api-basics.md`: `health.execute` 명령 형태와 현재 지원 endpoint.
- `references/evidence-map.md`: 수면, 활동, 심박, 혈압, 체성분 지표별 연구·가이드라인 근거와 답변 예시.
- `references/response-policy.md`: 근거 언급 방식, 답변 범위, 위험 수치 대응, 표현 제한.

## 작업 흐름

1. 사용자의 요청이 컨디션/건강 데이터 기반 조언이면 `health.execute` 로 필요한 데이터를 조회한다.
2. 첫 범위에서는 `GET /api/v1/health/me/latest` 를 기본 조회로 사용한다.
3. 데이터가 없으면 데이터가 없다고 말하고, Samsung Health 동기화가 필요하다고 안내한다.
4. 데이터가 있으면 `response-policy.md` 와 `evidence-map.md` 기준으로 해석한다.
5. 사용자의 데이터와 직접 관련된 연구·가이드라인 근거를 1-2개만 짧게 언급한다.
6. 진단명, 질병 확정, 약 복용, 치료 지시는 하지 않는다.
7. 답변은 "의학적 조언"이라고 표현하지 않는다. "일반 건강정보 참고이며 의학적 진단이나 치료 조언을 대체하지 않는다"로 제한한다.
8. 위험 수치가 보이면 일반 코칭보다 전문 상담 또는 즉시 도움 요청 안내를 우선한다.

## 출력 형식

사용자가 형식을 지정하면 그 형식을 따른다. 형식이 없으면 아래 섹션 순서를 사용한다. 핵심은 "요약 → 근거 → 주의할 점 → 추천 행동" 이며, 각 근거는 반드시 "사용자 데이터 → 짧은 해석" 형태로 쓴다. 연구·가이드라인은 한 문장 이내로만 붙이고 장황한 문헌 목록처럼 만들지 않는다.

```md
건강 데이터 요약:
- {사용자 요청 범위} 기준으로 보면, {가장 중요한 건강 데이터 2~3개} 때문에 {생활 관리 관점의 짧은 판단}입니다.

근거:
- 수면: {duration_minutes}분, 수면 점수 {sleep_score}점 → AASM/SRS 성인 수면 권고에 비춰보면 {짧은 해석}.
- 활동: {step_count}보, 활성 시간 {active_minutes}분 → WHO 신체활동 가이드라인과 웨어러블 활동량 연구를 참고하면 {짧은 해석}.
- 심박/혈압: 심박 {heart_rate_bpm}bpm, 혈압 {systolic_bp}/{diastolic_bp} → AHA/ACC 혈압 기준과 AHA 심박 자료를 참고하면 {짧은 해석}. 단일 측정값으로 진단하지 않는다.

주의할 점:
- ...

추천 행동:
- ...

참고:
- 이 응답은 Samsung Health 데이터와 공개 연구·가이드라인을 바탕으로 한 일반 건강정보 참고이며, 의학적 진단이나 치료 조언을 대체하지 않습니다.
```

사용자가 "3줄로 요약"을 요청하면 섹션 제목을 쓰지 않고 정확히 3줄만 출력한다. 3줄은 아래 역할을 따른다.

```md
1. 요약: {가장 중요한 사용자 데이터 2~3개} 기준으로 {생활 관리 관점의 판단}.
2. 주의: {사용자 데이터와 연결된 주의할 점}. 진단이나 치료 지시처럼 쓰지 않는다.
3. 행동: {낮은 위험의 추천 행동 1~2개}. 필요한 경우 전문가 상담 또는 재측정을 안내한다.
```

사용자가 자신감을 확인하는 입력에는 "괜찮다/안 괜찮다"로 단정하지 말고, 수면/활동/심박/혈압 데이터와 근거를 붙여 "무리하지 않는 조건에서 가능해 보인다", "회복을 우선하는 편이 좋다"처럼 답한다. 부족한 지표가 있으면 부족하다고 말하고 실행 팁을 제안한다.
답변은 항상 "진단"이 아니라 "건강정보 참고 코칭"으로 제한한다.
근거가 필요한 답변에는 "AASM/SRS 성인 수면 권고에 비춰보면", "WHO 신체활동 가이드라인을 참고하면", "AHA/ACC 혈압 분류 기준상"처럼 출처를 짧게 드러내되, 결론은 가능성과 참고 수준으로만 말한다.
