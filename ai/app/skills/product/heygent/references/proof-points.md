# Proof Points

## 실행 기록

- TaskRun은 사용자의 요청이 실제 실행 단위로 바뀐 결과입니다.
- StepRun은 긴 작업을 모델 호출, 도구 실행, 승인 대기, 결과 정리 같은 단계로 나누어 기록합니다.
- 이 구조 덕분에 "AI가 무엇을 하는지 모르는 상태"를 줄이고, 진행 상태를 화면에 보여 줄 수 있습니다.

## 실시간 복구

- 작업 이벤트는 WebSocket과 이벤트 시퀀스를 통해 화면에 반영됩니다.
- 사용자는 긴 작업 중에도 상태 변화를 확인할 수 있습니다.
- 화면을 다시 열어도 작업 흐름을 복원하는 방향으로 설계되어 있습니다.

## 에이전트 루프

- 모델은 필요한 경우 도구 호출을 선택하고, 실행 결과를 다시 맥락에 반영합니다.
- 도구 호출과 응답은 transcript로 남겨 재확인 가능한 흐름을 만듭니다.
- 승인 대기가 필요한 단계는 StepRun 상태와 연결해 사용자가 통제할 수 있게 합니다.

## 스킬 런타임

- 스킬은 단순 설명 문서가 아니라 절차, 참고 자료, 도구 사용 규칙을 묶습니다.
- 에이전트별 스킬 구성으로 할 수 있는 일의 범위를 제한하거나 확장할 수 있습니다.
- 로컬 도구 실행은 제한된 런타임과 워크스페이스 기준을 따라야 합니다.

## 작업 보드

- 작업 보드는 담당자, 상태, 댓글, 하위 작업, 실행 이력을 유지합니다.
- 대화가 흘러가도 작업 단위는 남기 때문에 후속 요청과 인수인계가 쉬워집니다.
- 에이전트가 여러 명일 때 누가 어떤 일을 맡는지 보여 줄 수 있습니다.

## 기억과 개인화

- 메모리 구조는 반복되는 사용자 선호와 맥락을 다시 활용하기 위한 기반입니다.
- 기억은 무조건 사용하는 것이 아니라 필요할 때 recall, writeback, reconcile 흐름으로 다룹니다.
- 사용자 경험은 "매번 처음 설명하는 AI"에서 "반복 작업을 이해하는 AI"로 확장될 수 있습니다.

## 멀티 디바이스와 로컬 브릿지

- 웹은 채팅, 작업 보드, 설정, 실행 상태 확인을 담당합니다.
- 모바일은 채팅, 알림, STT, 건강 데이터 흐름을 담당합니다.
- Galaxy Watch와 Samsung Health는 건강 맥락을 가져오는 접점입니다.
- IoT 디스플레이는 작업 상태를 별도 화면으로 보여 주는 접점입니다.
- 로컬 브릿지는 클라우드만으로 처리하기 어려운 PC 작업을 제한된 범위 안에서 연결합니다.
