# User Flows

## 기본 요청 흐름

1. 사용자가 자연어로 요청합니다.
2. 팀장 에이전트가 의도와 필요한 역할을 판단합니다.
3. 요청은 TaskRun으로 생성됩니다.
4. 필요한 작업은 StepRun으로 나뉩니다.
5. 에이전트는 스킬과 도구를 사용해 단계별로 실행합니다.
6. 결과와 진행 상태는 작업 보드와 실시간 화면에 반영됩니다.

## 외부 서비스 작업

1. 사용자가 Notion, Gmail, Mattermost, SRT 같은 작업을 요청합니다.
2. 에이전트는 연결된 스킬의 절차와 제약을 확인합니다.
3. 필요한 인증이나 승인 단계가 있으면 사용자 확인을 받습니다.
4. 실행 결과는 작업 상태와 함께 남습니다.

## 멀티 디바이스 흐름

1. 사용자가 웹이나 모바일에서 요청을 시작합니다.
2. 긴 작업은 실시간 상태로 확인합니다.
3. 모바일 알림이나 IoT 디스플레이로 진행 상태를 받을 수 있습니다.
4. 건강 데이터처럼 디바이스에서 온 맥락은 관련 에이전트의 참고 정보로 사용됩니다.

## 로컬 브릿지 흐름

1. 사용자가 PC에서 처리해야 하는 작업을 요청합니다.
2. 로컬 브릿지는 허용된 워크스페이스와 명령 범위 안에서 실행합니다.
3. 실행 결과는 TaskRun과 StepRun의 근거로 남습니다.
4. 위험하거나 민감한 작업은 승인과 제한 범위를 우선합니다.
